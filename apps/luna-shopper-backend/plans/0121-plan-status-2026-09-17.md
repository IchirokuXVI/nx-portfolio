### 1.1 0087 A shop list waits for the same yes a price does

- **Written:** 2026-09-06, commit `51447db6`, PR #235 (plan only).
- **What it proposed:** DEZA crawl availability is written from `outcome.entry.itemId`, which a
  `CANDIDATE` row also fills, so an unconfirmed fuzzy match writes per shop availability into
  catalog. The fix was a harvester table `source_entry_availability` (`entryId`,
  `sourceLocationId`, `available`, `observedAt`, `runId`, unique on the first two), written for
  mapped and unmapped shops, and copied into catalog only from `ACTIVE` rows, on accept or
  `createItem`. `SourceEntryAcceptResult` gained `availabilityWritten` and
  `availabilityConflicts`. `setAvailability` skipped a write older than
  `availabilityObservedAt`. `harvest.revert` deleted the run's rows. `HarvestDocument` gained
  `shops` and `available_at`.
- **Not built:** 0 code hits for `source_entry_availability`, `SourceEntryAvailability`,
  `availableAtShops` and `available_at`.
- **The defect it describes was still present:** `run-report.sink.ts` (about lines 323 to 327)
  fills `itemByExternalId` from `outcome.entry.itemId`, and lines 406 to 430 use that map for
  `setLocationAvailability`. `activeItemByExternalId` is used only for scope availability.
  `supermarket-location-item.service.ts` (about 180 to 212) has no `observedAt` comparison.
- **What changed since:**
  - 0103 (#316) moved availability writing out of the runner into the orchestrator and
    `run-report.sink.ts`, so the plan's line references to `deza-catalog.runner.ts` are stale.
    0103 also cut harvest document version 2 (`scopes`, `prices[]`) with no `shops` or
    `available_at`. 0087 assumed an extension of version 1.
  - 0118 (#384) copies availability to target scopes, and its availability writes carry no run id.
  - 0119 (#386) gates scope and shop availability behind `writes`
    (`PRICES_AND_AVAILABILITY`, `PRICES`, `AVAILABILITY`).
  - 0106 (#340) and 0107 (#342) changed how shops and source locations arrive.
  - Admin 0014 (#234) is the queue 0087 section 9 targets.
- **Open items the plan listed:** no backfill of a newly mapped shop, no batch accept, no
  availability history, no screen designed.

### 1.2 0095 A price says what it is per

- **Written:** 2026-09-06 in PR #250, rewritten 2026-09-09 in PR #305 (units became base units).
- **What it proposed:** a `PriceBasis` enum (`UNIT`, `KILOGRAM`, `HUNDRED_GRAMS`, `LITER`,
  `HUNDRED_MILLILITERS`, `WASH`, `METER`), `toComparable` and `comparableUnitOf` in contracts, a
  nullable `unitPriceBasis` on `item_prices`, `supermarket_items` and `source_entry_prices`,

  harvest document v2, per source mapping (Mercadona only when `bulk_price` agrees, Carrefour from
  `measure_unit`), an admin picker, and search ranked by `comparablePrice`. It retired backlog
  0011, which was deleted.
- **Not built:** 0 hits for `comparablePrice` and `comparableUnit`. The only `PriceBasis`-like hit

  - 0103 (#316) cut harvest document v2 as a price per scope (`prices[]` replaces `price` and
    `unit_price`). 0095's `HarvestDocumentUnitPrice.per` assumes a v2 that was never cut.
    `harvest-document-2.schema.ts` has no `per`.
