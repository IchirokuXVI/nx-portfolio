# 0144: a generated list is called a basket, everywhere

> The last plan of the series recorded in `0130`. Needs every backend plan from `0131` to
> `0143`, and velista `0090` to `0095`. It changes no behaviour.
>
> The thing was named `generated list` by plan `0050`, when it was a list that a run
> generated once and froze. The client has said `basket` since velista `0052`, the admin
> contracts say "`baskets` are `generated_lists`" (`admin-dashboard.messages.ts:140`), and
> after this series the name is wrong twice over: a `LIVE` basket is generated by nothing,
> and no basket is a list, because `0136` deleted its lines. `0130` section 3 therefore
> ruled that everything **born** in the series says `basket`, and left the things that
> already existed to this plan, last, when half of them are gone. Doing it first meant
> renaming three tables, fifty seven core files and thirty messages that `0136` then
> deletes.
>
> So for the length of the series the code says both words: `basket_sources.basketId`
> points at `generated_lists.id`, and `/v1/baskets/:id/rows` sits beside
> `/v1/generated-lists/:id/share-link`. This plan ends that.
>
> Prerequisite reading: `0130` sections 3 and 13. `CLAUDE.md` on the OpenAPI document, the
> wire types, deploys and `tools/release/rules.mjs`. The memory notes "Tier 2 compose states
> env separately", "OpenAPI regeneration", "Shell patching traps", "Prettier in this repo"
> and "Backend image runtime manifests". Nothing else: this plan is an inventory and a
> mapping, and both are below.

## Brief for the agent

Rename `generated list` to `basket` in the database, core, contracts, the NATS subjects,
the events, the realtime rooms and keys, the gateway routes, the configuration, the velista
client, the admin back office, the e2e support and the generated documents, with no change
of behaviour and no period in which both names are accepted.

### Constraints

- **No behaviour changes.** The acceptance test is that every spec passes unchanged except
  for the names in it. A spec that needs any other edit is a finding: stop.
- **No alias.** No view with the old table name, no gateway route answering the old path,
  no subject listened to under two names, no client accepting two event names. The project
  has no external consumer, and an alias is a second rule somebody has to remember to
  delete.
- **One mechanical commit per layer**, in the order of section 10, each of them green by
  itself. A reviewer reads a rename by trusting that a commit does one thing.
- Use `git mv` for every file, so history follows. Never delete and recreate.
- Rename with the language service or a checked script, never with a blind `sed` over the
  tree: `generatedListId` is a substring of nothing else today, and that is luck. After
  every scripted pass, read the diff. Mind CRLF and the other traps in the memory note on
  shell patching.
- Never run prettier over a directory, and always with `--end-of-line auto` (memory note).
  A rename that also reformats cannot be reviewed.
- Regenerate `openapi.json` and the wire types, never hand edit them. A huge diff that is
  only reordering is normal here (memory note "OpenAPI regeneration").

## 1. The rule

1. `generated list`, in any casing and any separator, becomes `basket`. `generated lists`
   becomes `baskets`.
   `GeneratedList` to `Basket`, `generatedList` to `basket`, `generated_list` to `basket`,
   `generated-list` to `basket`, `GENERATED_LIST` to `BASKET`, and the room word
   `generated` to `basket`.
2. **Where the new name already exists, the two are the same thing and merge.** The
   participant read is already `BasketView`. If a `GeneratedListView` survived `0136`,
   it is the same basket seen by its owner, and section 4 says which name each keeps.
3. **Where the old name was only a prefix on a word that already says basket**, the prefix
   goes and nothing is doubled: `GeneratedListBasketLineView` was never going to become
   `BasketBasketLineView`.
4. A `generatedListId` column, field, parameter or property becomes `basketId`.
5. Product copy is not touched. velista calls the screen "shopping lists" and the route
   `shopping-lists`, which is what a person calls it. That is a product name and stays.
6. History is not rewritten. A comment that says "plan `0050` called this a generated list"
   is telling the truth.

  table is renamed.

- Take the full list from the database, not from this table:

```sql
SELECT c.relname, c.relkind FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'public' AND c.relname LIKE '%generated%';
SELECT conname FROM pg_constraint WHERE conname LIKE '%generated%';
SELECT typname FROM pg_type WHERE typname LIKE '%generated%';
```

  After `up`, all three answer no rows. That is the migration's integration spec.

```sql
-- up, in this order: columns while the old table names still read naturally, then tables,
-- then the names that hang off them
ALTER TABLE "generated_list_participants" RENAME COLUMN "generatedListId" TO "basketId";
ALTER TABLE "generated_list_share_links" RENAME COLUMN "generatedListId" TO "basketId";
ALTER TABLE "generated_lists" RENAME TO "baskets";
ALTER TABLE "generated_list_participants" RENAME TO "basket_participants";
ALTER TABLE "generated_list_share_links" RENAME TO "basket_share_links";
ALTER INDEX "ix_generated_lists_owner" RENAME TO "ix_baskets_owner";
-- ... one ALTER INDEX per index row of the table above
ALTER TABLE "basket_participants"
  RENAME CONSTRAINT "fk_generated_list_participants_list" TO "fk_basket_participants_basket";
-- ... one RENAME CONSTRAINT per constraint row
ALTER TYPE "generated_list_status" RENAME TO "basket_status";
```

`down` is the same statements with the two names swapped, in the reverse order. No data
moves in either direction, so neither is lossy. `COMMENT ON` text that spells an old name
is rewritten in `up` and restored in `down`.

Entities: `@Entity({ name: 'baskets' })` and the two others, every `@Index` and `@Unique`
name, every `@JoinColumn({ name: 'basketId' })`, and the property `generatedListId` to
`basketId`. **Raw SQL is where a rename hides**: every `.sql.ts` file under core spells
table and column names in strings that no compiler checks
(`generated-list-sharing.sql.ts`, `generated-list-members.sql.ts`, `line-claim.sql.ts`,
`trips.sql.ts`, `suggestions.sql.ts`, `basket-order.sql.ts`, `purchases.sql.ts`,
`admin-list.service.ts:463` and `:549`). Only the integration specs prove them, so the
integration target runs on a slot before the pull request opens.

## 11. The deploy

A rename is neither an expansion nor a contraction, and `migrate.ts` assumes every
migration is one or the other. For the length of one rolling restart:

- an old core pod reads `generated_lists`, which no longer exists, and answers 500.
- an old gateway sends `generatedList.*`, which no new core listens to, and the request
  waits until the proxy cuts it at fifteen seconds (memory note "Assistant timeout is
  Envoy's default").
- an open basket screen loses its socket and reconnects into the new room.

That window is accepted, because the alternative is the alias this plan refuses, and
because nothing but this team's own clients is on the other end. Make it short and make it
safe:

- Deploy to staging first and watch the rollout finish before anybody opens a basket.
- **A rollback is two steps, in this order**: `helm rollback`, then the migration's `down`
  through `node migrate.js` from the older image. `helm rollback` alone leaves old code
  on new names, which is the same outage without an end. Write that into the pull request,
  and into the release notes for the production release that carries this plan.
- Production takes it inside an ordinary release (`release.yml`), at a quiet hour.

## 13. Tests

No new rule, so almost no new spec:

1. **The migration, integration.** `up` on a database holding baskets, participants and
   links leaves every row readable through the renamed entities, and the three catalog
   queries of section 3 answer no rows. `down` restores every name, and `up` runs again.
2. **Route order.** `DELETE /v1/baskets/:id/participants/mine` reaches `leave`, and `GET
   /v1/baskets/live` and `/shared` are not swallowed by `:id`.
3. **The stream**, on a slot, by hand or in the realtime integration spec when one exists:
   a renamed event reaches a socket in a renamed room.
4. Every existing spec, unchanged except for names. `wire-contract.spec.ts`,
   `openapi-document.spec.ts` and `wire-types.spec.ts` are the three that fail when a layer
   was missed, and they are the ones to read first when something is red.
