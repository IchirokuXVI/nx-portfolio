### 2.1 0087

The defect it describes is still present. `harvester/.../harvest/run-report.sink.ts` fills
`itemByExternalId` from `outcome.entry.itemId`, which a `CANDIDATE` row also fills, and uses
that map to write shop availability. Only scope availability uses `activeItemByExternalId`. So
an unconfirmed fuzzy match still writes availability for each shop into the catalog. The
reasons it needs a rewrite are in 0121 section 1.1, and nothing since changed them.

### 2.2 0126 to 0129, Open Food Facts

- **0126** builds a new framework free library, `libs/luna-shopper/open-facts`. Nothing of it
  exists. The pattern it copies (the LIDL, DEZA and Carrefour libraries) is unchanged, so it
  can be built as written. Its measurements are dated 2026-09-19 and are worth taking again.
- **0127** adds `item_facts`, `item_facts_raw`, four columns on `items`, seven `itemFacts.*`
  messages and gateway routes. Its premise holds: `imageUrl` is still null on imports and there
  is no facts table. What is stale:
  - It names `Item.category`, which 0166 (#525) replaced with `item_categories` rows.
  - It does not know `items.packCount` (0162).
  - It names `1757600000000-BrandLinks` as the latest catalog migration, and the latest is now
    `1758200000000-ShopSections`.
  - Its line references in `catalog.mappers.ts`, `item.service.ts` and `catalog.messages.ts`
    moved.
- **0128** adds a `PRODUCT_FACTS` run mode. `HarvestRunMode` still has three values. It names
  `1757400000000-RunPresets` as the latest harvester migration, and three came after it. The
  index list its enum rebuild must recreate needs checking against those three.
- **0129** keeps a copy of each product photo. It reverses the rule that images are not
  rehosted, which is the owner's call.
