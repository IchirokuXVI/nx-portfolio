## Brief for the agent

### Objective

Let a curator see, choose and clear the step of a product sold by the kilo or by the litre,
in the product record, in the unit the shopper reads. The write goes through the admin item
routes that `0261` widens, and a refused value shows its sentence under the field.

### Context

What `0261` gives this plan (its sections 0 to 3):

- `quantityStep: number | null` on `ItemView`, and on the admin create, update and batch
  update, in grams or millilitres. Null means today's ladder (S4). A set step applies at every
  amount, with no change of grain at a kilo (S1, S4).
- The values are a closed list, `QUANTITY_STEPS`: 1, 5, 10, 25, 50, 100, 200, 250, 500 and
  1000 (S2). The gateway checks it with `@IsIn`, so a value off the list is a
  `validation_failed` with a field error on `quantityStep`, and the OpenAPI document lists the
  ten values as an enum (section 3).
- Only a product sold by the kilo or the litre carries a step: `KILOGRAM` or `LITER`, no size,
  no weight (S3). Anything else is refused with `item_quantity_step_not_allowed`, a 400 whose
  details carry `allowed`, `defaultUnit`, `unitSize` and `approxWeight` (section 2.2).
- An edit that makes a stepped product a pack or a piece is refused unless the same edit
  sends `quantityStep: null` (section 2.2).
- Only a person writes the step, so there is no `quantityStepSetBy` (S7). A run's weight fill
  skips a stepped product and counts it in `skippedHasStep` (S6).

What the back office has today: the product record is drawn from one descriptor (`ITEMS`,
`items.ts:170` onward). A number field has no unit word, no choices and no text for an empty
value (`resource-field.ts:255` to `260`, `resource-view.ts:202` to `205`). An enum field holds
strings with static labels (`resource-field.ts:298` to `307`), while the step is a number on
the wire whose words depend on the unit ("250 g" or "250 ml").

### Target state

1. In the "sold" section, a "Step" field sits after the size and the weight, only while the
   product as the form holds it is sold by the kilo or the litre (`0261` S3).
2. While the page reads, a set step reads "250 g", "1 kg", "50 ml" or "1 L". A product with no
   step reads, greyed: "Default: 25 g, then 250 g from 1 kg" (or the millilitre line).
3. While the page is a form, the field is a select. Its first option is the default line,
   which saves `null`. The ten steps of `0261` S2 follow, drawn in grams or millilitres
   ("1 g" to "1 kg", "1 ml" to "1 L") after the product's unit (writer decision B).
4. Typing a weight, typing a size, or choosing a unit other than `KILOGRAM` or `LITER` hides
   the field and empties it, so the same save sends `quantityStep: null`, which `0261` section
   2.2 requires of that edit.
5. A refusal shows its sentence under the field.
6. The admin models read the step from the regenerated `wire-types.ts`.

## 2. The field

### 2.1 Where and when

In `items.ts`, a `number` field `quantityStep`, label `catalog.items.quantityStep`, after
`approxWeight` in the "sold" section (`:411` to `417`), `nullable: true`.

`shown(held)` is true when `held.defaultUnit` is `KILOGRAM` with both `unitSize` and
`approxWeight` empty, or `LITER` with `unitSize` empty and `approxWeight` empty. That is
`carriesQuantityStep` of `0261` section 1, read over the draft. Write it as one local function
`measuredUnitOf(held)` that answers `'g'`, `'ml'` or `null`, so `shown`, the unit word, the
option labels and the default line read one rule. The admin keeps its own copy, as `0068` did
for its rule, and its spec runs it over each row of the table of `0246` section 1.

### 2.2 A select of the ten steps

The field's new `choices` hook (section 3) answers `QUANTITY_STEP_CHOICES`, a constant in
`items.ts` holding the ten values. It is typed so that it must equal the members of the
generated union:

```ts
type WireStep = NonNullable<Wire.CatalogItemView['quantityStep']>;
const QUANTITY_STEP_CHOICES = [1, 5, 10, 25, 50, 100, 200, 250, 500, 1000] as const satisfies readonly WireStep[];
```

with a type level assertion in the spec that every `WireStep` is in the list. If `0261`'s
`@IsIn` reaches the wire types as plain `number` and not as a union, the spec compares the list
with the `enum` of `quantityStep` in `apps/luna-shopper-backend/gateway/docs/openapi.json`
instead. A step added to `0261` then fails the admin's spec, not a curator's save.

Each option is drawn through the field's `unit` hook: "1 g", "5 g", "10 g", "25 g", "50 g",
"100 g", "200 g", "250 g", "500 g", "1 kg" for a product by the kilo, and the same in
millilitres to "1 L" for one by the litre. The first option is the default line of section 2.3
and holds the empty value, which an emptied nullable field submits as `null`
(`resource-field.ts:71` to `82`). That option is the control to go back to the default; no
press is needed beside it (writer decision D).

### 2.3 What is drawn

| State | Read | Form |
| --- | --- | --- |
| A step is set | "250 g", "1 kg", "50 ml", "1 L" | The select on "250 g". Under it: "Set for this product. A run does not give it a weight while it has a step." |
| No step | Greyed: "Default: 25 g, then 250 g from 1 kg" | The select on its first option, "Default: 25 g, then 250 g from 1 kg". No line under it |

The read value goes through `formatGrams` (`product-format.ts:30` to `34`) for grams and a
millilitre twin for millilitres, so the step reads as a shopper reads an amount. The line
under a set step is the field's `note` (`resource-field.ts:184`) and says what `0261` S6 means
for the curator. It names no source, because only a person sets a step (S7).

### 2.4 A kind change empties it

`shown` already empties a hidden field in the draft (`resource-field.ts:156` to `158`). So
typing a weight on a loose cheese, typing a size, or choosing `UNIT` hides the step, and the
same save sends `quantityStep: null` beside the new size, weight or unit. That is the edit
`0261` section 2.2 accepts. A spec asserts the request body, because without the `null` the
server refuses the save.

A switch between `KILOGRAM` and `LITER` keeps the value and redraws the options in the other
unit (writer decision G). Both units take the same ten values.

### 2.5 A refusal

- `validation_failed` with a field error on `quantityStep` (a value off the list, which the
  select cannot send, so a stale build or another client): the server's sentence is drawn
  under the field by `messagesFor` (`record-store.ts:234` to `243`). Nothing to add.
- `item_quantity_step_not_allowed` (a step on a product that is not sold by the kilo or the
  litre, which the form cannot send either): a case in `gateway-error-key.ts` beside `0068`'s
  two (`:105` to `113`), a key `resource.error.itemQuantityStepNotAllowed`, and an entry in
  `errorFields` (`items.ts:444` to `450`) that names `quantityStep`.
- A field that holds a message is drawn whatever `shown` says (`resource-field.ts:158`), so a
  refusal on a product the form would hide the field for is still visible.

## 3. Three generic number field hooks

`NumberField` (`resource-field.ts:255` to `260`) gains three optional methods, each a method
for the reason `read` is one (`:121` to `125`):

- **`unit?(held: Partial<T>): NumberUnit | null`**, where `NumberUnit` is
  `{ word: string; format(value: number, locale: string): string }`. `toCell`
  (`resource-view.ts:202` to `205`) reads a set value through `format` in place of the bare
  number, on the record page and in any list cell of the field. A box draws `word` after it.
  `null`, or no method, keeps today's drawing.
- **`choices?(held: Partial<T>): readonly number[] | null`**: the field is drawn as a select of
  those values, each labelled through `unit.format` when there is a unit, and with an empty
  first option when the field is `nullable`. The draft holds the chosen value as it holds a
  typed one, so `min`, `max`, `integer` and the submit are unchanged. A value the row holds
  that is not in the list is shown as an extra option, so a stale row is visible and not
  silently replaced. `null`, or no method, keeps the box.
- **`emptyText?(held: Partial<T>): FieldMessage | null`**: drawn greyed in place of "None"
  while the page reads, as the label of the empty first option of a select, and as the
  placeholder of an empty box. `null`, or no method, keeps "None".

None of the three changes what is submitted. `read` stays display only on a field that is not
editable; `format` writes the same value with its unit, so the rule of `read` (`:111` to `113`)
does not apply.

## 7. Decisions

### The owner's, 2026-11-09 (fixed)

- **U4. The curator decides the step of a product.** Small products (saffron) need a small
  step, big ones (a whole chicken, tuna, meat) a much bigger one. A step per product, set in
  the back office. A product with no step keeps today's default. This plan is the back office
  half of it, over backend `0261`.

U1, U2, U3, U5 and U6 of the same date are velista and backend decisions and change nothing
here. The values, the kinds, the meaning of null, the refusals and the run's behaviour are
`0261`'s S1 to S8, not this plan's.

### The writer's, open to the owner

- **A. The field follows `0261` S3 in the draft.** It is shown only while the held row is sold
  by the kilo or the litre, so the form never offers what the server refuses.
- **B. A select of the ten steps, not a free box.** The values are a closed list of ten
  (`0261` S2). A box makes the curator guess the list and learn it from a refusal; a select
  shows it, in the unit the shopper reads ("100 g", "1 kg"), and cannot send a value off it.
  Ten options fit one select with no search. The cost is one generic hook (`choices`), which
  any later closed list of numbers reuses.
- **C. Generic hooks, `unit`, `choices` and `emptyText`, and not a special control.** The
  record page draws every field from the descriptor. A one off control for one field breaks
  that. An enum field does not fit: it holds strings with static labels, and the step is a
  number whose words follow the unit.
- **D. The default is the select's first option, with no press beside it.** `0068` needed
  "Use the chain's weight" because a box has no visible way back; a select does.
- **E. The product list does not show the step in its size column.** The column is what tells
  two products apart (`items.ts:340` to `342`): the 1 litre from the 1.5. A step does not tell
  products apart, and on the list it would read like a size ("100 g" beside a 100 g pack). The
  record is where a curator sets it. A curator who wants the loose products with no step yet
  needs a filter, which is a gateway change (question 2).
- **F. `item_quantity_step_not_allowed` gets an admin key; a `validation_failed` keeps the
  server's text.** The admin keys every coded refusal it maps to a field
  (`gateway-error-key.ts`); a field error already arrives as the server's sentence.
- **G. A switch between `KILOGRAM` and `LITER` keeps the value.** Both units take the same ten
  values, and the options redraw in the new unit in front of the curator. Nothing in
  production is sold by the litre today (backend `0246` section 1).
- **H. The line under a set step says what `0261` S6 means.** A curator who stepped a product
  should know that a run will not turn it into a kilo piece by itself.

## Not in this plan

- The velista side: a line stepping by the product's step (velista `0186`).
- The create form of the harvester queue (`entries-queue-page.ts`). A product made from a row
  starts with no step, which `0261` section 2.3 states for a run too.
- A bulk "set step" action over many products.
- A list filter or column for the step (decision E).
- Showing the run report's `approxWeightsSkippedHasStep` on the run page. That is a harvest
  screen; a later admin plan picks it up if the owner wants it.
