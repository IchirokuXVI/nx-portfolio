The design for plan 0046: the profiles page behind the account screen, with the selector, add and delete, and the single-line name rule. Server half: backend 0049. Phone only, 390 by 844, Night only. Generated from the committed *.dc.html artboards and the notes in canvas.json.

Scale

Plan 0046. A profile is how the app knows where somebody shops: postal codes, chains included or excluded (the franchise, never one shop), and the saving that makes a second stop worth it. Profiles are several, named, switchable; one is the default that catalog reads and generated runs use when nothing says otherwise.

Every user already has one (backend 0049 creates it lazily), so the page never has a create-your-first wall.

RULE R1: A PROFILE NAME IS ONE LINE, ALWAYS. The selector row, the open list, 0045's generation sheet and anywhere else render it with ellipsis, and the layout never grows to fit it. Plus and trash never move. The server caps names at 64 characters so the truncation is cosmetic; the full name stays the control's accessible name, so a screen reader is never handed the ellipsis.

PLUS CREATES IMMEDIATELY: a fresh profile, selected, name focused, no modal asking for a name first. Unnamed profiles render as the localized default, My profile.

THE TRASH IS ABSENT with one profile, because the last one cannot be deleted. Deleting the default promotes another, and the confirm names which. Excluded chains are struck through and stay visible, never hidden, so they can come back.
