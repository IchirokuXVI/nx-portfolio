Velista: what changed while you were not looking

The design for plan 0093: a basket follows its lists now, so a line can appear, ask for a different amount, take another name or leave while somebody is halfway down an aisle. A mark on the row, a disabled row where a line left, a banner that counts what is new, and a sheet that tells each change in words. Phone only, 390 by 844, Night only: every colour role here is already proven on Day. Generated from the committed *.dc.html artboards and the notes in canvas.json.

Scale

THE PROBLEM. The basket used to be a snapshot somebody generated. It follows its lists now, so what is on the screen in a shop can change under the person holding the phone: a flatmate adds bread, somebody doubles the eggs, a line is deleted.

None of that can be silent. A shopper who walks past the dairy aisle because the milk was not on the list, and finds out at the till that it was added twenty minutes ago, has been failed by the screen rather than by the flatmate.

THE WINDOW BELONGS TO EACH VIEWER, AND TO THE SERVER'S CLOCK. What is new is not "changed in the last hour": it is "changed since this person last looked". The server keeps that cursor per participant, so a phone that spent the change in a pocket still shows it, and a phone with a wrong clock shows it for the right length of time.

THE CLIENT HOLDS NO CLOCK. It draws what the read says. It never starts a timer that ends a mark, never stores "last seen", and never compares a change's time to anything. A mark appears and disappears because a read said so.

A MARK IS A SHAPE AND A WORD. "New" and "Changed", a dot and a tag, at the trailing end of the name line, in the accent role. Never the warning colour: amber is this app's accent, and a line a flatmate added is not a fault.

NOTHING MOVES. A marked row is drawn where the server's order put it, never lifted to the top: a list that rearranges under a thumb is the thing 0053 refused. The tag sits inside the name, so a marked row and an ordinary one are the same height.

IT IS PART OF THE ROW'S ONE NAME, not a second thing to hear: "Milk, new on the list".

A LINE THAT LEFT STAYS ON SCREEN, DISABLED. Every entry of the row left the coverage and this viewer has not seen it go, so the server keeps sending the row and the screen keeps drawing it. Somebody standing in front of the shelf has to be told, and a row that simply vanished is a row they will look for.

NOTHING ON IT IS A CONTROL: no glyph, no reel, no price, no chevron, and it opens no sheet. The Tab key passes it by, and a screen reader still reads it in order.

THE STRIKE IS NEVER ALONE. "No longer on the list" is under the name, because a line through text is shape and colour with no words in it.

IT COUNTS TOWARD NO NUMBER. The progress sentence is the server's, and the tools bar's pair and the chip row's pair all leave it out.

THE BANNER IS UNDER THE TOOLS BAR AND OUTSIDE IT. The bar stays exactly as tall as it was (0079): a banner inside it would push the search and the chips down a phone every time a line moved on somebody else's list.

ONE ROW, ONE BUTTON: a dot, the count in a sentence, and a chevron. It is announced politely when the number appears or moves, and not on every redraw.

IT IS THE SERVER'S COUNT. It goes when a read says zero, never because somebody tapped it. It is drawn on a finished basket too, because what changed is still worth reading.

NO ANIMATION. An announcement and a layout shift at once is two interruptions, on a screen somebody is reading in an aisle.

THE SHEET IS THE ONE LAYOUT NOT SEEN BEFORE. Title, then one entry per change, newest first. An entry is two lines: the sentence, and a muted line with who, which list and when, each part present only when the reader is entitled to it. A guest is served no list and often no person, and then there is simply no second line rather than an empty one.

AN ENTRY IS NOT A BUTTON and opens nothing. A change is a fact, and the row it is about is one dismiss away.

THE "NEW" TAG IS THE SAME TAG A ROW WEARS, and it is the server's flag, not a comparison of the date beside it.

SHOW MORE KEEPS FOCUS on the button and announces how many arrived, which is the pattern 0088 already uses for older trips.

WHAT COUNTS AS HAVING SEEN IT. The client tells the server "I have read everything through this change" only when the tab is visible AND either a marked row is half on screen or the sheet is drawing entries, AND both have been true for a second and a half.

IT SENDS AN ID, NEVER A TIME, so a change that arrives between the render and the request stays new.

EVERY WAY OF BEING WRONG IS THE QUIET ONE. Offline: the marks stay. Tab hidden the whole time: nothing is sent. Marked rows below the fold: nothing is sent for them, and the banner still counts them. Sheet opened and shut in a second: nothing. A background refetch acknowledges nothing at all, ever.

TWO DEVICES ARE ONE VIEWER. Reading it on the phone clears it on the tablet at its next read. Accepted.
